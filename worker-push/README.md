# Forge push relay

Cloudflare Worker for Forge device/agent identity registration, explicit pairing, authorization, replay-protected agent events, and direct APNs delivery.

The design, and what the relay's operator can and cannot see, is described in [the push relay](../docs/security/push-relay.md).

## Trust model

- Device and agent identity private keys never leave their owners.
- APNs device tokens go directly from Forge to this Worker and are encrypted in D1.
- Agents send signed semantic events and never receive APNs tokens.
- Devices directly approve and revoke agent authorizations.
- The APNs `.p8` key exists only as a Worker secret.

## Local setup

```bash
npm install
npx wrangler d1 create forge-push
# Put the returned database_id in wrangler.toml.
npm run db:migrate:local
```

Create `worker-push/.dev.vars` for local testing only; it is gitignored:

```dotenv
APNS_PRIVATE_KEY_P8="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----"
APNS_KEY_ID="..."
APNS_TEAM_ID="..."
PUSH_TOKEN_ENCRYPTION_KEY="<base64url encoding of 32 random bytes>"
```

Generate the encryption secret, for example:

```bash
openssl rand -base64 32 | tr '+/' '-_' | tr -d '=\n'
```

Then:

```bash
npm run dev
npm run typecheck
npm test
```

## Cloudflare deployment

Authenticate Wrangler and create D1:

```bash
npx wrangler login
npx wrangler d1 create forge-push
# Update database_id in wrangler.toml.
npm run db:migrate:remote
```

Store secrets interactively. Do not put them in `wrangler.toml` or D1:

```bash
npx wrangler secret put APNS_PRIVATE_KEY_P8
npx wrangler secret put APNS_KEY_ID
npx wrangler secret put APNS_TEAM_ID
npx wrangler secret put PUSH_TOKEN_ENCRYPTION_KEY
npm run deploy
```

The topic in `wrangler.toml` is `com.tingouw.forge`, and the database ID and Firebase project there belong to the maintainer's deployment. Replace all three with your own. The iOS development build registers a sandbox token; TestFlight/App Store registers a production token.

## Implemented API

Public proof-of-possession bootstrap:

- `GET /healthz`
- `POST /v1/registration-challenges`
- `POST /v1/registrations`

Signed device API:

- `PUT|DELETE /v1/devices/:deviceId/push-endpoint`
- `GET /v1/devices/:deviceId/pairings/:pairingId`
- `POST /v1/devices/:deviceId/pairings/:pairingId/approve`
- `GET /v1/devices/:deviceId/authorizations`
- `DELETE /v1/devices/:deviceId/authorizations/:agentId`

Signed agent API:

- `POST /v1/agents/:agentId/pairings`
- `GET /v1/agents/:agentId/pairings/:pairingId`
- `GET /v1/agents/:agentId/authorizations`
- `DELETE /v1/agents/:agentId/authorizations/:deviceId`
- `POST /v1/agents/:agentId/events`

The current Worker sends APNs inline. Before multi-user production deployment, place accepted events on a Cloudflare Queue and move APNs delivery/retries into the Queue consumer.

## Android FCM

The Android app uses its existing Android Keystore P-256 identity for relay registration and pairing. FCM tokens are encrypted in D1 exactly like APNs tokens. The Worker alone holds the Firebase service account and sends through FCM HTTP v1.

Configure the project and encrypted credential:

```bash
# wrangler.toml: FCM_PROJECT_ID = "your-project-id"
npx wrangler secret put FCM_SERVICE_ACCOUNT_JSON < ~/.config/forge/firebase-service-account.json
npm run deploy
```

The Firebase Android package must be `com.tingouw.forge`. Keep `android/app/google-services.json` local and never commit service-account JSON.

## End-to-end encrypted notification content

Android, iOS, and macOS notification content is encrypted by the agent before relay submission. Each authorized agent/device pair has a random AES-256-GCM key generated by the agent. The key is sent only through the mutually authenticated encrypted WebSocket, signed by the agent P-256 identity, verified by Flutter, and imported into Android Keystore.

FCM receives only a high-priority data message. iOS APNs receives a mutable-content alert carrying the same opaque envelope. macOS APNs receives an opaque content-available message for decryption by Forge while the app is running, containing `version`, opaque `eventId`, `keyId`, `nonce`, and `ciphertext`. `ForgeEncryptedMessagingService` authenticates/decrypts locally and creates the notification. The Worker rejects plaintext Android events. D1 records `event_type = encrypted` and `session_id = encrypted`; the real type, session, title, and body are unavailable to the relay, FCM, and D1.
