# Antigravity (`agy`) provider integration

Status: **available when agy is installed and signed in**. Pi Go creates a dedicated profile at `~/.pi-go/agy` (or `$PI_GO_CONFIG_DIR/agy`; override with `PI_GO_AGY_HOME`) without changing the user's normal Antigravity profile. The Forge Web/isolated Gemini 3.8 Flash Low MCP path was verified with classifier-checked tool calls. The server on port 7346 was not replaced. If `agy` is missing, Codex continues to work and selecting an `agy/` model reports installation instructions; if signed out, model selection reports the exact terminal login command. Refresh models after sign-in.

## Required architecture

- Launch `agy -p --output-format stream-json --model <discovered-id> --disable-slash-commands` and consume bounded NDJSON events. `step_update` events are not necessarily token deltas. Capture the `conversation_id` from `init`, use `--conversation <id>` for subsequent prompts (never `--continue` for concurrent sessions), and close/cancel child processes on abort. Pi Go persists each successfully completed agy UUID in its session JSONL alongside the local transcript and MCP tool call/results; on a session switch or restart only the matching model/workspace binding is restored. A missing binding with existing assistant history fails closed instead of discarding context. Changing model/workspace invalidates the UUID.
- Pi Go initializes the dedicated agy HOME under `~/.pi-go/agy` (or `$PI_GO_CONFIG_DIR/agy`) with a deny-native permission policy and its own MCP config. That config holds no executable path. Its only server runs `/bin/sh -c 'exec "$PI_GO_AGY_MCP_BINARY" --agy-mcp-stdio'`, and each agy turn injects the running pi-go-agent executable in `PI_GO_AGY_MCP_BINARY`, so rebuilding or moving the binary needs no config change. Classifier runs leave it empty, so no tool child can start. A legacy config that pinned an absolute executable path is migrated automatically. Pi Go never overwrites any other modified config. Sign in once in a terminal using `HOME="$HOME/.pi-go/agy" agy` (adjust for `PI_GO_CONFIG_DIR` or `PI_GO_AGY_HOME`), then refresh the model list. A missing `agy` executable disables only this provider. Block workspace-local and inherited MCP servers. The agy policy must deny `read_file(*)`, `write_file(*)`, `read_url(*)`, `execute_url(*)`, `command(*)`, and `unsandboxed(*)`, and allow only `mcp(pi-go-agent/*)`. Do not use `--dangerously-skip-permissions`.
- Implement a private, authenticated MCP endpoint/stdio server that exposes the approved Pi Go tools. Every invocation must run through the existing safety classifier **before** tool execution. Safety approval requests require a connection to the original session's approval lifecycle; otherwise deny rather than silently approve. Keep the classifier on its separately configured model/provider (never route classifier calls through agy). The MCP response must be returned in the same agy turn, not as a subsequent user prompt.
- Agy executes its own MCP tool calls internally, so the Pi Go `agent.Provider` interface cannot receive tool calls and hand them to the normal Go tool loop. The MCP server must emit tool/safety events back to the session runtime separately. Merely translating agy's `step_update` to text events would lose approval and audit semantics.
- Dynamic `agy models` enumeration must not block or fail Codex model listing when agy is unavailable. Filter invalid model IDs, bound command runtime/output, and only advertise the agy entries after the policy/MCP checks above succeed. Bind agy's model ID namespace to `agy/` so the existing API-provider router cannot treat it as an API credential name.

- The current MCP stdio child advertises `read`, `write`, `replace`, and `bash`; browser and cron tools are not yet exposed to agy. Denied operations return MCP `isError` without executing. The HTTP turn bridge emits tool start/update/end events to the existing app/web protocol, but manual approval is not implemented for agy; rejected classifier decisions remain denied. Agy print mode has no automatic turn deadline (`--print-timeout 0`); a user abort still cancels the subprocess and active MCP tools.
- Live acceptance: agy 1.2.10 under `/tmp/agy-isolated.UmIqd8` is signed in. Native `view_file`, `write_to_file`, and `run_command` returned user-configured deny-rule errors. Forge Web at `http://127.0.0.1:7357` authenticated over a temporary Cloudflare WSS tunnel to the isolated server on port 7358 after its **public** browser key was added to only that server's whitelist. The UI streamed `WEB_OK`, then showed a live MCP `read` tool panel and the returned sentinel plus a classifier-generated completion summary. The temporary same-origin public-key export page and endpoint were removed after pairing; the whitelist remains in `/tmp/pi-go-agy-server-config`. Flutter rebuild/tests on this host remain blocked by the unaccepted Xcode license. The running production agent server was not replaced.

- YOLO on an agy session bypasses only the Pi Go MCP classifier; the dedicated agy deny-native permission policy, authentication token and MCP tool allowlist still apply. The switch cannot be changed during an active turn.
- Pi Go prepends MCP-only tool-routing guidance to the first `agy -p` prompt (agy exposes no system-prompt flag); resumed agy turns inherit that context. Claude Code receives the same guidance via `--append-system-prompt`. Both are usability hints, not safety controls: CLI native-tool denial and the authenticated MCP classifier remain mandatory.

- Agy's `stream-json` responses tested with Gemini 3.8 Flash Low (agy 1.2.11) exposed only `agent_response` text and `thinking_tokens` usage, not readable thinking text. The adapter forwards non-empty text only when agy explicitly emits `agent_thinking` or `thinking` step updates. It never turns answer text or token counts into a fabricated Thinking summary.

## Verification gates

1. With a disposable workspace, ask agy to read/write a sentinel and execute a shell command directly: all three must fail without mutation. Ask it to use the MCP equivalents: only classified and permitted operations succeed.
2. Confirm `agy -p` streams progress and MCP calls without producing duplicate answer text. Abort a long call and verify both child and server stop.
3. Verify concurrent Pi Go sessions use distinct agy conversation IDs and that `--conversation` resumes only the matching session.
4. Exercise classifier failure and approval-needed paths: they must fail closed, with no tool execution. Test global/workspace MCP and settings overrides against the verifier.

## Compaction

agy has no compaction command: in print mode, `/compact` is sent as an ordinary prompt and the conversation keeps growing. Pi Go's `/compact` therefore reports an error for agy sessions instead of summarizing a local transcript that agy never reads. Start a new session to reduce context.

## Gemini as classifier and summarizer

An `agy/…` model may be the classifier model used for safety decisions and turn summaries. agy has no schema or system-prompt flag, so each request is a fresh one-shot `agy --print=<prompt>` conversation. The prompt contains the classifier instructions, the output JSON schema and the payload.

- The reply must be exactly one JSON object, optionally in a single code fence. It then gets the same field validation as the OpenAI output-tool path, and any failure denies the operation.
- The run uses the verified MCP-only policy, the private `~/.pi-go/classifier-workdir`, and empty MCP turn credentials. The pi-go-agent MCP child therefore refuses to start, so the run has no usable tools.
- Afterwards, files and directories in the dedicated agy home named exactly after the conversation UUID (optionally with an extension) are deleted so classifier conversations do not accumulate. Symlinks are not followed. If no such entry exists, the agent logs this once.
- The prompt, including the payload, is passed in argv because agy has no stdin prompt option. This matches ordinary agy turns.
